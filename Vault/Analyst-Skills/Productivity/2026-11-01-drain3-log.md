## What’s new and why it matters
一句話結論：與其替每種錯誤寫關鍵字規則，不如讓 Drain3 把 log 歸納成「樣板」，只在出現沒看過的樣板時通知一次。已知的問題不吵你，新的問題才會冒出來。 遇到的問題 最常見的 log 告警做法是：log 裡出現 error ，就通知。 這種規則在第一週還算好用，很快就會變成噪音。一個依賴服務重啟，幾百行 connection refused 一起噴出來，通知響不停。看完才發現是已知問題，下次又響。 接著開始加例外：這種錯誤不要報，那種超過幾次才報。規則越寫越多，卻還是會漏掉真正重要的事，也就是 第一次出現的新錯誤 。 其實真正想問的是：「這行 log 跟我以前看過的，是不是同一種？」 這就是 log 樣板（template）要解決的事。 connection refused addr=10.0.0.8:5432 attempt=2 和 connection refused addr=10.0.0.41:5432 attempt=4 其實是同一種，只是變數不同。把變數抽掉，剩下的骨架就是樣板。每個樣板記下來，之後只要出現沒見過的，才值得通知。 Drain3 是一個做這件事的 Python 套件，演算法是 Drain，本身不用訓練資料，一行一行餵進去就會即時歸納。 手把手步驟 準備環境 只需要裝一個套件： pip install drain3 == 0.9.11 下面的結果都是…
